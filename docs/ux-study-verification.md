## 확인한 내용

- `npm test`: 177개 통과. `npm run check`, `npm run build` 통과.
- 실제 320×740 및 390×844 화면에서 참여 안내·설정·탐색 확인. 320px에서 문서 너비 320px로 가로 넘침 없음.
- 동의 전·기록 거부 상태에서 탐색해도 UX 이벤트 0건.
- 동의 후 말머리 선택, 홈 이동, 전체 메뉴 열기, 큐시트 찾기, 1994년 선택, 학기·프로그램·회차 선택, 확대·회전이 로컬 D1에 저장됨.
- 기록을 중단한 후 이동해도 저장 이벤트 29건으로 유지됨.
- API의 비인가 로그 조회는 403. 일반 회원·moderator·정지 계정 거부와 admin 허용은 서버 테스트로 확인.
- 허용하지 않은 텍스트·URL·회원 ID 필드, 관리 화면 이벤트는 서버에서 거부.
- SQLite에서 수집 → 집계 → 방문별 조회, 테스트 방문 기본 제외, 중복 재전송 제거, 일일 한도 확인.
- 실제 관리자 로그인 후 로그 화면의 브라우저 확인은 사용자가 추후 직접 확인하기로 함.

## 외부 배포

사용자가 `account:read`, `user:read`, `pages:write`, `d1:write` 권한 연결을 승인했고 Wrangler 연결을 완료했다. 별도 Pages 프로젝트와 D1 `voku-ux-study`를 생성했다. D1 ID는 `961918e6-2dba-40f3-bc3b-185db8fc2bce`이며 이 DB에만 스키마를 적용했다.

- 공개 실험 주소: `https://voku-ux-study.pages.dev/`
- 관리자 로그 주소: `https://voku-ux-study.pages.dev/#/ux-log`
- 서버 런타임에는 기존 공개 `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY`를 연결했다. 관리자 비밀 키는 사용하지 않았다.
- 사용자 승인 후 실험 사이트 `/`, `/?auth=recovery` 두 복귀 주소를 Supabase Auth에 추가했다. 기존 `https://voku.pages.dev/` Site URL과 기존 10개 복귀 주소는 유지했다.
- 실제 카카오 로그인 후 실험 호스트의 `/ux-log`로 복귀함을 확인했다. 로그인된 일반 회원의 로그 접근은 차단됐다.
- 공개 주소와 짧은 게시글 주소 200, 비회원 로그 API 403, 검색 제외 헤더 확인.
- 실제 모바일 조작 25건이 원격 D1에 저장되고 모두 테스트 방문으로 분류됨을 확인했다. 테스트 기록은 기본 집계에서 제외된다.
- 390px 공개 화면에서 문서 가로 넘침 없이 참여 안내가 표시됐다. 본문에 복사된 큐시트·게시글 주소의 실제 링크 대상이 실험 호스트로 유지됐다.
- 기존 운영 주소는 실험 번들을 포함하지 않고 정상 200 응답을 유지했다.

코드는 `codex/voku-ux-study` 브랜치로만 관리하며 운영 `main`에는 합치지 않는다. 기존 게시글·회원 테이블의 변경이나 마이그레이션은 없었다.
