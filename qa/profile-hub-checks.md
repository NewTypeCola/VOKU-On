2026-10-13. 사용자가 커밋·푸시·운영 배포를 보류했다. 이번 변경은 로컬 작업 트리에만 있다.

- 전체 메뉴의 프로필과 커뮤니티의 닉네임 모두 `/account`의 내 프로필로 진입한다.

- 내 활동에는 내 글·내 댓글·신고 내역, 저장 목록에는 큐시트·게시글 필터가 있다. 기존 `/saved` 바로가기도 유지한다.
- 저장 목록 UI를 공유하여 해제·실행 취소 동작을 유지한다. 기존 `/account?tab=saved` 링크는 저장한 게시글을 표시한다.
- 프로필의 저장 탭에 직접 들어와도 아카이브 목록을 로드한다.
- 정보 수정의 미저장 보호를 유지하고, 수정 화면에서 돌아오면 출발한 프로필 탭·페이지를 복원한다.
- 전체 메뉴의 구성·85% 미리보기·모션과 별도 운영자 대시보드는 유지한다. 프로필 사진은 전체 메뉴와 게시글의 기존 작성자 사진 위치에 표시한다.

검증 결과:

- `npm run check`, `npm test` 154개, `npm run build`, `npm run check:performance` 통과.
- `qa/personal-polish.html`: 390×844와 320×568에서 각각 40개 검사 통과.
- 로컬 체험 모드에서 두 프로필 진입 경로, 활동·저장 두 메뉴와 활동 하위 신고 내역, 저장 큐시트 열람→원래 큐시트 탭, 저장 게시글 열람→원래 게시글 탭, 내 댓글 2페이지→댓글→원래 2페이지, 정보 수정→원래 저장 게시글 탭을 확인했다.
- 가로 넘침과 앱 콘솔 오류 없음. 실제 휴대폰 대신 모바일 크기의 브라우저에서 검사했다.
- 실제 회원정보나 운영 DB를 수정하는 테스트는 하지 않았다.

로컬 주소: `http://127.0.0.1:5221/#/account?back=%2Fboard`. 체험 계정으로 확인한다.


## 프로필 사진·소개 추가 (같은 날 후속)

- 사진 선택·교체·삭제를 회원정보 저장/변경 취소에 포함했다. 사진/소개만 편집해도 미저장 이동 보호가 작동하며, 실패해도 입력을 유지한다.
- JPG·PNG·WebP 원본 15MB 이하를 받아 중앙 정사각형 최대 512px JPEG/256KiB 이하로 변환한다. SVG 등 실행 가능한 형식을 거부하고 원본 EXIF를 재사용하지 않는다.
- 소개는 선택 300자, 나만 보기로 표시한다. 사진 공개 안내와 선택 이미지 미리보기를 제공한다.
- 직접 업로드한 사진만 공개 게시글에 반영한다. 기존 소셜 로그인 사진을 공개 사진으로 자동 전환하지 않는다. 카카오 사진은 직접 설정하기 전까지 기존 본인 메뉴에서만 유지한다.
- 기존 `tab=reports` 링크는 내 활동의 신고 내역을 선택한다. 저장 목록과 설정 복귀 주소는 그대로 유지한다.
- 사진 저장용 공개 `profile-photos` 버킷, 본인 업로드/미사용 사진 삭제 RLS, 불변 경로·8개 보관 제한, 소개의 본인 전용 응답을 로컬 SQL로 준비했다. 이미 적용된 마이그레이션의 내용은 바꾸지 않았다.
- 새 파일: `supabase/migrations/20261013102857_profile_photo_and_introduction.sql`. CLI로 생성했으며 **운영 DB에는 미적용**이다. 서버가 아직 준비되지 않은 로컬 연결 화면에서는 새 필드 저장을 비활성화한다.
- 데이터베이스 검증은 실제 Postgres 엔진인 PGlite에서 수행했다. 공개 글에 사진 경로만 노출, 운영진에게도 타인 소개 미노출, 타인 경로 업로드/도용/삭제·덮어쓰기 거부, 현재 사진 삭제 금지, 삭제 후 기본 상태 복귀, 길이/형식/용량 검증, 이전 클라이언트의 필드 보존을 확인했다.
- 실제 Supabase Storage 서비스의 업로드/정리 호출 검증은 운영 마이그레이션 적용 후 별도 확인이 필요하다. 이번에는 실제 회원정보·스토리지·운영 DB를 변경하지 않았다.
- 로컬 체험 계정에 예시 로고와 소개를 저장해 새로고침 후 유지, 내 프로필/전체 메뉴/게시글 사진 일치, 게시글에 소개가 표시되지 않음을 확인했다.
- 모바일 브라우저 회귀 검사: 사진 준비/형식 제한, 소개/사진 변경 보호, 실패 후 재시도, 사진 삭제·취소·저장, 신고 위치 등 40개 항목. 실제 휴대폰에서의 사진 보관함 권한/HEIC 변환은 확인하지 않았으며 지원 형식은 UI에 명시했다.
- 홈의 초기 로딩 용량을 유지하려고 사진 변환과 체험 프로필 저장 처리를 필요한 화면/동작에서만 불러오게 했다. 성능 기준 통과: initial JS 819,874B, home JS 849,886B.
- `docs/oauth-branding/privacy.html`의 프로필 항목에 사진 공개와 소개 본인 표시를 반영한 로컬 문구를 준비했다. 공개된 문서는 변경하지 않았다.

참고 조사: [네이버 밴드 프로필 공식 가이드](https://docs.band.us/d/promotion/profileguide). 사진·이름·소개로 식별하고 근황·관심사를 나누는 방식을 확인했다. VOKU On의 후속 후보는 당시 역할, 참여 프로그램, 활동 시기, 최근 근황이며 이번에는 별도 항목으로 추가하지 않았다.

## 프로필 수정 화면 가독성과 전체 메뉴 (같은 날 후속)

- 추가 프로필 항목은 보류했다. 기존 프로필/수정 헤더 오른쪽에 앱의 동일한 전체 메뉴를 연결했다. 전체 메뉴 구성·85% 미리보기·모션·터치 영역을 유지한다.
- `내 정보 수정` 버튼과 `내 설정` 화면 제목·문서 제목을 `프로필 수정`으로 통일했다. 저장 동작은 `프로필 저장`으로 표시한다.
- 수정 화면에서 중복되던 저장 프로필 요약을 빼고, 사진·기본 정보·소개를 각각 구분했다. 로그인 정보는 편집 항목과 분리하고 항목 사이 구분선을 추가했다.
- 입력값 16px을 유지하면서 제목·라벨·보조 안내의 대비와 여백을 조정했다. 관련 스타일은 프로필 화면에서만 불러온다.
- 메뉴를 열고 닫아도 입력과 복귀 경로를 유지한다. 메뉴 이동·로그아웃에 미저장 보호를 연결했고, 이동 취소 시 현재 메뉴와 편집 화면을 그대로 유지한다.
- `qa/personal-polish.html`: 390×844, 320×568에서 각각 40개 통과. 미저장 취소/승인, 저장 실패/재시도, 사진/소개 편집 및 원래 저장 탭 복귀를 포함한다.
- `qa/menu-polish.html`: 두 크기에서 각각 27개 통과. 미저장 이동·로그아웃 차단, 85% 미리보기, 닫기 후 포커스·스크롤·입력 유지, 빠른 재열기와 동작 줄이기를 포함한다.
- 실제 로컬 체험 화면에서 내 프로필과 수정 화면의 메뉴 열기/닫기, 헤더로 포커스 복귀, 문서 제목, 320px 입력칸 경계와 가로 넘침 없음을 확인했다. 실제 휴대폰 검증은 아니다.
- 타입/자료 검사, 단위·DB 테스트 154개, 빌드, 성능 기준을 통과했다. 커밋·푸시·운영 배포·운영 DB 변경은 하지 않았다.

## 최종 점검과 운영 DB 적용 (2026-10-13)

위 로컬 단계 이후 사용자가 최종 점검·DB 마이그레이션·커밋·푸시·운영 배포를 승인했다.

- `npm run check`, `npm test`(154개), `npm run build`, `npm run check:performance`, `node scripts/check-home-build.mjs`, `git diff --check`를 다시 통과했다. 운영 빌드에 로컬 사진 예시 글은 포함되지 않는다.
- 모바일 브라우저 320×568·390×844에서 프로필 40개, 전체 메뉴 27개 검사를 각각 다시 통과했다. 저장 실패/재시도, 사진·소개 편집 보호, 원래 목록·탭 복귀, 메뉴 닫기·포커스·85% 미리보기·동작 줄이기를 포함한다. 실제 휴대폰 사진 보관함 권한 시험과는 구분한다.
- 최종 크기: 초기 JS 819,947B, 홈 JS 849,959B, 초기 CSS 240,687B, 홈 CSS 254,951B. 성능 예산을 유지한다.
- 운영 Supabase 프로젝트 `awvnzjdtdcdcjtfinuuy`에 `20261013102857_profile_photo_and_introduction.sql`을 적용했다. 실제 서버 기록은 `20261013112508_profile_photo_and_introduction`이다. 공개 사진 버킷과 소유자별 업로드/미사용 사진 삭제 정책, 본인 전용 소개, 기존 클라이언트 호환 래퍼를 확인했다.
- `qa/profile-release-check.sql`로 실제 DB의 익명·회원·게시판관리자 역할을 검사했다. 소개의 본인 전용 반환, 글의 사진 경로만 공개, 타인 경로 업로드·삭제 거부, 현재 사진 삭제 금지, 잘못된 사진/긴 소개 거부, 이전 클라이언트의 필드 보존이 통과했다. 모든 생성 자료는 롤백했고 시험 계정 잔여 0개를 확인했다.
- SQL 검사는 실제 파일 업로드가 아니라 DB 정책과 응답 범위를 확인한다. 실제 Storage 업로드/정리와 배포 화면은 아래 운영 확인에서 별도로 검사했다.
- Supabase 보안·성능 Advisor를 적용 전후 비교했다. 신규 경고는 없으며 기존 `community_action`의 security-definer 노출 경고 한 개가 줄었다. 기존 정책의 성능 제안과 비밀번호 유출 검사 경고는 이번 범위에서 변경하지 않았다. [DB Advisor 설명](https://supabase.com/docs/guides/database/database-linter), [비밀번호 보호 설명](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).
- 별도 운영자 대시보드와 운영자 계정의 회원 여부·역할은 수정하지 않았다.

## 운영 배포 후 확인

- 기능 커밋 `ac480ac326f5baf5f5172eda7d717124cceba506`을 GitHub `main`에 푸시했다. 해당 커밋의 Cloudflare Pages 검사가 성공했고 운영 `https://voku.pages.dev/`에서 새 UI를 확인했다.
- 사용자가 기존 카카오 회원으로 로그인한 뒤 공개 VOKU 아이콘과 임시 소개로 실제 저장을 시험했다. Storage에 512×512 JPEG(25,940B)가 생성되고 프로필 저장 RPC가 성공했다. 새로고침 후 사진·소개가 유지됐다.
- 저장한 사진이 내 프로필·전체 메뉴·기존 게시글 작성자 위치에서 정상 로드됐다. 사진 주소는 비인증 HTTP 200을 반환했으며, 게시글에는 소개가 표시되지 않았다. 소개 응답의 본인 제한은 앞선 실제 DB 권한 시험으로 검증했다.
- 운영에서도 390×844·320×568에서 가로 넘침이 없고, 수정 입력칸은 16px이며 화면 안에 들어왔다. 프로필과 수정 화면의 전체 메뉴를 모두 확인했다.
- 앱의 사진 삭제·소개 비우기·프로필 저장으로 시험 파일을 Storage API에서 정리했다. DB에서 사진 경로 null, 소개 빈 문자열, 시험 Storage 객체 0개를 확인했다. 시험 전의 소셜 사진 표시 상태까지 복원했다. 실제 회원 화면의 증거 이미지는 공개 저장소에 추가하지 않았다.
- 회원 역할·닉네임·학번·기수·게시글·댓글은 변경하지 않았다. 별도 운영자 대시보드의 계정과 권한도 변경하지 않았다.
