# 운영 예시 정리와 전체 메뉴 스크롤 (2026-10-13)

## 변경 범위

- 전체 메뉴의 오른쪽 여백을 패널 밖에서 스크롤 영역 안으로 옮겼다. 메뉴 글자·버튼 위치와 기존 모션·85% 미리보기는 유지하고 스크롤바만 앱 화면 오른쪽 끝에 놓는다.
- 홈 배너 설정을 비웠다. 이미지가 없으면 기존 2:1 크기의 빈 영역을 표시하며 링크·이미지·배너 점·재생 버튼·자동 넘김은 없다. 빈 영역에서는 홈의 좌우 탭 이동을 사용할 수 있다. 추후 최대 10개 배너 설정과 기존 이미지 전환 기능은 유지한다.
- 예시 배너/사진 파일 8개를 `public/home/`에서 `assets/home/`으로 옮겨 운영 배포에 복사하지 않는다. 생성 프롬프트와 원본 파일은 보존하고 개발 모드 사진 예시 경로만 바꿨다. 빌드 검사에서 예시 이미지와 로컬 글이 운영 산출물에 없는지 확인한다.

## 운영 데이터 정리

- `sample_batch=community-ux-2026-10-11`로 식별한 예시 공지·글 30개, 예시 댓글 41개를 확인했다. 사용자가 추가 승인한 ‘테스트’, ‘사진 테스트’ 2개와 댓글 3개까지 포함했다.
- 변경 전 ID·상태·수정일을 작업용 로컬 파일에 보관했다. 대상 32개 글과 44개 댓글을 잠그고 스냅샷의 상태·수정일이 동일한지 확인한 뒤 한 트랜잭션에서 앱의 기존 `status=deleted` 방식으로 삭제 처리했다. 제목 검색이나 전체 테이블 삭제를 사용하지 않았다.
- 처리 직후 공개 글 0개, 공개 댓글 0개. 실제 DB의 `anon` 역할로 글·댓글·첨부사진이 각각 0개 조회됨을 확인했다. 게시판·검색·홈·공유에서 기존 읽기 권한 검사가 삭제 글을 제외한다.
- 첨부사진 3개는 삭제된 글과 함께 운영 노출에서 제외된다. 비공개 Storage의 원본을 영구 폐기하는 작업은 하지 않았다. 기존 발급된 서명 URL은 최대 5분 만료 정책을 따른다. Storage 메타데이터를 SQL로 삭제하지 않았다.
- 회원·프로필·계정에 저장한 큐시트·권한·원본 아카이브와 별도 운영자 대시보드는 변경하지 않았다. 스키마 변경이 없어 새 DB 마이그레이션은 필요하지 않다.

## 검증

- `npm run check`, `npm test`(154개), `npm run build`, `npm run check:performance`, `node scripts/check-home-build.mjs`, `git diff --check` 통과.
- 초기 JS 819,947B, 홈 JS 848,710B, 초기 CSS 240,691B, 홈 CSS 254,849B. 기존 성능 기준 통과.
- 320×568 전체 메뉴 회귀 검사 27개 통과. 메뉴 스크롤 영역의 오른쪽과 화면 오른쪽은 모두 320px이며 가로 넘침이 없다.
- 390px에서도 메뉴 오른쪽과 화면 끝이 일치하며, 320px에서는 마지막 메뉴에 키보드로 이동했을 때 스크롤 끝(58px)까지 도달한다. `menu-scroll-edge-320.png`로 기록했다.
- 홈 스와이프 브라우저 검사 14개 통과. 빈 배너에서 홈 탭 이동이 가능하고 일반 게시글의 짧은 주소도 정상으로 열린다. 합성 터치 이벤트로 검사했다.
- 운영 빌드의 320px 홈에서 빈 배너 1개, 배너 이미지/조작 버튼 0개, 공지/게시글 링크 0개를 확인했다. 인기글·사진·동문소식·최근글의 빈 상태 안내가 정상이다.
- 실제 휴대폰 검사가 아닌 모바일 크기의 브라우저 검사다.
